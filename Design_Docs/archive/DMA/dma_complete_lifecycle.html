Complete lifecycle of one DMA transfer for IMU data, from boot configuration through 14 bytes moved to interrupt handling

PHASE 1 — CONFIGURATION (happens once at boot, CPU does this)
1
CPU (via APB bus → bridge → DMA registers)
CPU writes SAR, DAR, TCR, CR for channel 0
SAR = 0x4000_1004 (SPI FIFO address — where the IMU bytes are)
DAR = 0x2000_0100 (DSRAM buffer — where the bytes should end up)
TCR = 14 (move 14 bytes)
CR = P→M, byte, no source inc, dest inc, circular, interrupt on, priority 7, ENABLE
2
DMA channel 0 FSM
FSM sees CR.EN = 1 → moves from IDLE to CONFIGURED
Copies SAR, DAR, TCR, CR into private working registers (shadow copies). Takes 1 clock cycle (5 ns). Then automatically moves to WAITING_FOR_REQUEST.
PHASE 2 — WAITING (DMA is armed, waiting for sensor data)
3
SPI peripheral
IMU sensor sends byte #1 over the SPI wire → SPI puts it into its FIFO
The SPI hardware clocks in data from the external IMU chip. Each byte goes into a small internal queue (FIFO). When the FIFO has at least one byte, SPI asserts dma_req[0] = 1 on the sideband wire. This wire goes directly from the SPI block to the DMA block — no bus involved.
4
DMA channel 0 FSM + arbiter
FSM sees dma_req[0] = 1 → raises ch_req[0] to the arbiter
The arbiter (priority encoder inside DMA) checks all 6 channels. Only CH0 is requesting. CH0 priority = 7. No competition. Arbiter outputs grant = 1. FSM moves to TRANSFERRING.
PHASE 3 — TRANSFERRING (one byte, two bus transactions)
5a
DMA AHB master — READ from SPI FIFO
DMA puts the SPI FIFO address on the AHB bus and reads 1 byte
DMA drives: HADDR = 0x4000_1004, HWRITE = 0 (read).
The AHB address decoder (hardwired logic on the bus, NOT part of DMA) sees the upper bits = 0x4, knows this is an APB range, routes to the bridge.
Bridge performs APB read from SPI FIFO → returns the byte on HRDATA.
DMA captures the byte in its tiny internal buffer register.
5b
DMA AHB master — WRITE to DSRAM
DMA puts the DSRAM buffer address on the AHB bus and writes the byte
DMA drives: HADDR = 0x2000_0100, HWRITE = 1 (write), HWDATA = the byte.
Address decoder sees upper bits = 0x2, routes directly to DSRAM (no bridge needed — DSRAM is on AHB).
DSRAM stores the byte. Returns HREADY = 1 (done).
5c
DMA internals
Bookkeeping: ack the peripheral, update counters, release bus
DMA pulses dma_ack[0] = 1 for one clock cycle → SPI pops the byte from its FIFO.
Working counter: 14 → 13. Destination address: 0x2000_0100 → 0x2000_0101 (DINC=1).
Source address stays 0x4000_1004 (SINC=0).
FSM returns to WAITING_FOR_REQUEST. Arbiter re-evaluates.
PHASE 4 — REPEAT (steps 4-5 happen 13 more times)
6
Repeat for bytes 2-14
Each byte: arbiter grants → read SPI FIFO → write DSRAM → counter--
If another channel (say CH2 sonar, priority 5) requests during this process, the arbiter compares priorities. CH0 = 7 > CH2 = 5, so CH0 wins every time. CH2 waits until CH0 is done or CH0's FIFO empties.

After byte 14: working counter hits 0.
PHASE 5 — COMPLETION AND INTERRUPT
7
DMA channel 0 FSM
Counter = 0 → FSM moves to COMPLETE
Hardware sets SR.COMPLETE = 1.
Since CR.IE = 1 (interrupt enabled), the AND gate fires: dma_irq[0] goes HIGH.
This wire goes from DMA → CLIC (the interrupt controller).
8
CLIC → CPU
CLIC interrupts the CPU → CPU jumps to the DMA interrupt handler
CPU pauses whatever it was doing (EKF math). Saves its current position (program counter → mepc register). Jumps to the ISR (interrupt service routine) — a C function you wrote.
9
CPU (running ISR)
ISR reads SR, sees COMPLETE=1, clears it, signals EKF task
CPU reads SR via APB (same path as step 1, but reading).
Sees bit 0 = 1 (COMPLETE). Writes 1 to bit 0 to clear it (W1C).
dma_irq[0] drops to 0 (because SR.COMPLETE is now 0).
ISR posts a FreeRTOS semaphore: "EKF task, your IMU data is at 0x2000_0100."
ISR returns → CPU restores its previous position and resumes EKF math.
PHASE 6 — CIRCULAR RESTART
10
DMA channel 0 FSM
CIRC=1 → reload SAR, DAR, TCR → back to CONFIGURED → WAITING
No CPU involved. DMA resets itself: source back to 0x4000_1004, dest back to 0x2000_0100, counter back to 14. Ready for the next batch of IMU data in ~1 ms. The cycle repeats indefinitely.
