## 1 Purpose and scope

### 1.1 In scope

One AHB-Lite slave that converts AHB transfers in the `0x4000_0000` region into APB3
transfers on eleven peripheral windows, and returns the response. Includes the window
decode, the AHB↔APB state machine, the per-window access-rate divider, sub-word rejection,
and the peripheral timeout.

### 1.2 Out of scope

- `pclk` generation — `GARUDA-CLKRST-SPEC-001` §7.1.
- The peripherals themselves.
- The DMA's own APB config port, which is a peripheral on window 4 like any other.

### 1.3 What Rev 1.4 got wrong

Two things, and they are worth stating because both were internally contradictory rather
than merely suboptimal.

**The clock.** Rev 1.4 generated `pclk` by passing every second `hclk` pulse through an
integrated clock gate, and specified the result as 125 MHz with 50% duty. A gate that
passes alternate pulses of a 4 ns clock produces a 2 ns high time in an 8 ns period — 25%
duty. The stated mechanism cannot produce the stated waveform. A 25%-duty clock halves the
usable setup window for anything sensitive to the low phase and distorts hold margins
throughout the peripheral domain.

**The crossing.** Rev 1.4 asserted "no CDC is required" and gave no reason, while
`GARUDA_DMA_Controller_Design_Spec_v2_2` §15.3 implemented gray-code counters, a toggle
handshake and level synchronisers against that same `pclk`. Both documents cannot be right.
The conclusion of Rev 1.4 was correct and its reasoning absent; the DMA's implementation
was solving a problem that does not exist. §7.2 of this document supplies the proof, and
`GARUDA-DMA-SPEC-001` Rev 3.0 deletes the synchronisers.

## 6 Register map

**[N-6.1]** The bridge has no registers. It is transparent apart from the error responses
of §7.5–§7.7, which surface as precise faults in the accessing master. `mem_ctl`'s
`MEMCTL` register occupies offset `0x20` of window 8 and belongs to
`GARUDA-MEM-SPEC-001`, not to the bridge.

### 6.1 Window map

Generated from `GARUDA-SYS-001` `apb.windows`.

**The window number IS the address nibble**: window *n* is at
`0x4000_0000 + 0x1000 x n`, and PSEL bit *n* is `haddr[15:12]`, exactly as
`ahb2apb_bridge.v` decodes it (`wire [3:0] win = haddr_i[15:12]`). There is no
window 0 — `0x4000_0000` is unmapped and faults.

## 7 Functional description

### 7.1 Transfer conversion

**[N-7.1]** An AHB transfer with `hsel_i` high, `htrans_i` = NONSEQ or SEQ, and a legal size
starts an APB transfer. The FSM runs IDLE → SETUP → ACCESS → DONE.

| State | `PSEL` | `PENABLE` | Duration |
|---|---|---|---|
| IDLE | 0 | 0 | until a request |
| SETUP | 1 | 0 | 1 `pclk` |
| ACCESS | 1 | 1 | 1 `pclk` × `APB_DIV`, extended while `PREADY` is low |
| DONE | 0 | 0 | 1 `pclk`, returns the response to `hclk` |

**[N-7.2]** `hreadyout_o` is held low from acceptance until DONE, stalling the AHB master.

**[N-7.3]** Minimum latency is 4 `pclk` cycles = 8 `hclk` cycles = 32 ns at `APB_DIV`=÷1.
A peripheral register access therefore costs the core about 8 cycles. At 7% bus
utilisation and a few dozen peripheral accesses per flight-loop iteration this is
immaterial; DMA exists so that per-byte peripheral traffic does not pay it.

### 7.2 Why no CDC is required — the proof

**[N-7.4]** `pclk` is generated by a toggle flop clocked by `hclk`
(`GARUDA-CLKRST-SPEC-001` [N-7.3]). Therefore:

1. Every `pclk` rising edge occurs simultaneously with an `hclk` rising edge.
2. The set of `pclk` edges is a proper subset of the set of `hclk` edges.
3. The phase relationship is fixed, known at design time, and constant — there is no
   drift, because both clocks derive from the same source with an integer ratio.
4. `pclk_phase_i` identifies, in the `hclk` domain, exactly which `hclk` cycle precedes a
   `pclk` edge.

**[N-7.5]** Consequently every transfer between the domains is sampled on an edge both
domains share. There is no window in which a `pclk` flop samples an `hclk` flop mid-transition,
because the two never transition at different times. Metastability requires a setup
violation from an unknown phase relationship; here the phase relationship is known and
constrained by static timing analysis like any other path.

**[N-7.6]** STA handles this with one `create_clock` and two `create_generated_clock`
statements. The `hclk`→`pclk` paths are timed as ordinary multi-cycle synchronous paths.
No synchronisers, no metastability, no CDC waivers, no gray coding.

**[N-7.7]** This is different in kind from the `tck`↔`hclk` boundary in the Debug Module,
which is a genuine asynchronous crossing with an unrelated clock source and does require
synchronisers.

**[N-7.8]** The `hclk`-side capture registers load on any `hclk` edge, and the `pclk`-side
FSM advances only on `pclk` edges. The bridge uses `pclk_phase_i` to guarantee that the
`hclk` side does not change the captured address or write data during the `hclk` cycle in
which the `pclk` side samples it. Assertion `a_capture_stable_at_phase` (§10) checks exactly
this.

### 7.3 Per-window access rate

**[N-7.9]** `APB_DIV` extends the ACCESS phase for a window by holding `PENABLE` asserted
for 1, 2, 4 or 8 `pclk` cycles before sampling `PREADY`.

**[N-7.10]** This is an access-rate mechanism, not a clocking mechanism. The peripheral's
flops still receive `pclk` at 125 MHz. It therefore accommodates an IP whose *interface*
timing needs longer phases, but **not** an IP whose internal logic cannot meet the 8 ns
`pclk` period. For that case the only remedies are `DIVSEL` on `clk_div`
(`GARUDA-CLKRST-SPEC-001` §6.2), which slows the whole chip, or a different IP. This
distinction is stated because it is easy to assume `APB_DIV` solves both, and it does not.

**[N-7.11]** All eleven windows default to ÷1 on the assumption that a simple UART, SPI or
I²C block in a 28 nm process meets 125 MHz. If an IP datasheet later shows otherwise, that
window's `APB_DIV` changes and nothing else in the chip is affected.

### 7.4 Word-only access

**[N-7.12]** Only `hsize_i` = WORD (`3'b010`) is accepted. BYTE and HALFWORD accesses
produce a two-cycle AHB ERROR without generating any APB transfer.

**[N-7.13]** Rationale: APB3 has no byte enables. A bridge that accepted a byte write would
have to read the word, merge, and write back — three transfers for one, and a
read-modify-write against a peripheral whose registers may have read side effects, clear-on-read
fields or write-1-to-clear semantics. Silently doing that is worse than refusing. Rejecting
it means the fault is precise and points at the instruction that caused it.

**[N-7.14]** Every peripheral register in this chip is 32 bits and word-aligned, so no
correct firmware performs a sub-word peripheral access.

### 7.5 Timeout

**[N-7.15]** If `PREADY` for the selected window is not asserted within 16 `pclk` cycles of
entering ACCESS, the bridge abandons the transfer, deasserts `PSEL` and `PENABLE`, and
returns a two-cycle AHB ERROR.

**[N-7.16]** 16 cycles is chosen as comfortably longer than any legitimate wait in this
peripheral set — none of them inserts more than 2 — while being short enough that a hung
peripheral costs 128 ns rather than a stalled flight loop.

**[N-7.17]** The timeout is the only thing standing between a defective or unclocked
peripheral and a permanently stalled bus. `GARUDA-AHB-SPEC-001` [N-7.18] relies on it: the
interconnect has no timeout of its own precisely because the only slave that can stall
indefinitely has one here.

**[N-7.18]** A timeout leaves the peripheral in an undefined state — it may have latched a
write. No recovery is attempted. The reasonable firmware response is to treat the access
fault as fatal and reset.

### 7.6 Unmapped windows

**[N-7.19]** `haddr[15:12]` values with no window — `0x0` (the removed SPI slave) and
`0xB`–`0xF` — assert no `PSEL` and return a two-cycle AHB ERROR.

### 7.7 SLVERR

**[N-7.20]** A window asserting `PSLVERR` with `PREADY` causes the bridge to return a
two-cycle AHB ERROR. Peripherals assert `PSLVERR` for unmapped offsets within their own
window and for illegal field writes, as defined in each peripheral's own specification.

**[N-7.21]** All three error sources — sub-word, unmapped window, `PSLVERR` — produce the
identical AHB two-cycle ERROR. The master cannot distinguish them, and does not need to:
all three are firmware bugs, and `mepc` identifies the instruction.

## 9 Clock, reset and power

**[N-9.1]** The bridge is the only block in the chip spanning `hclk` and `pclk`. Both are
synchronous (§7.2). `tck` does not appear here.

**[N-9.2]** `hreadyout_o` resets to **0**, not 1. The bridge spans two reset releases:
`hreset_n` deasserts two `hclk` cycles after the stretch counter expires, `preset_n` two
`pclk` cycles after that (`GARUDA-CLKRST-SPEC-001` §7.17). Between those two moments the
AHB side is live and the APB side is still in reset. Resetting `hreadyout_o` low holds any
AHB master that addresses the APB region during that window, rather than letting it see a
bogus OKAY from a bridge whose peripheral side cannot yet respond.

**[N-9.3]** `hreadyout_o` is released only when both `hreset_n_i` and the synchronised
`preset_n_i` are deasserted. This is the requirement `GARUDA-CLKRST-SPEC-001` §5.2 refers
to.

**[N-9.4]** Power: the `pclk` domain at half `hclk` halves the dynamic power of the
peripheral clock tree and of every peripheral flop, which together are the largest flop
population outside the core. This is the whole reason `pclk` exists as a real divided clock
rather than an access-rate trick — `APB_DIV` alone would deliver the same interface rate
while leaving every peripheral flop toggling at 250 MHz, saving nothing.

**[N-9.5]** Each window's `PSEL` is a natural enable term for a per-peripheral clock gate.
The gate belongs to the peripheral, not the bridge, so that a peripheral with internal
timers — the PWM, for instance — can keep running while unselected. The bridge exposes
`psel_o` and makes no gating decision.

## 10 Assertions

```systemverilog
// --- APB3 protocol: SETUP is exactly one cycle with PSEL and no PENABLE
a_apb_setup: assert property (
  @(posedge pclk_i) disable iff (!preset_n_i)
  $rose(|psel_o) |-> !penable_o ##1 penable_o);

// --- PENABLE never asserts without PSEL
a_penable_needs_psel: assert property (
  @(posedge pclk_i) disable iff (!preset_n_i) penable_o |-> |psel_o);

// --- PSEL is one-hot or zero
a_psel_onehot: assert property (
  @(posedge pclk_i) disable iff (!preset_n_i) $onehot0(psel_o));

// --- address and write data stable for the whole APB transfer
a_apb_addr_stable: assert property (
  @(posedge pclk_i) disable iff (!preset_n_i)
  (|psel_o && !done) |-> $stable(paddr_o) && $stable(pwrite_o));
a_apb_wdata_stable: assert property (
  @(posedge pclk_i) disable iff (!preset_n_i)
  (penable_o && pwrite_o && !pready_sel) |=> $stable(pwdata_o));

// --- THE no-CDC property: the hclk-side capture is stable on the shared edge
a_capture_stable_at_phase: assert property (
  @(posedge hclk_i) disable iff (!hreset_n_i)
  pclk_phase_i |-> $stable(addr_cap) && $stable(wdata_cap) && $stable(ctl_cap));

// --- every pclk edge coincides with an hclk edge (checked, not assumed)
a_pclk_on_hclk: assert property (@(posedge pclk_i) hclk_i);

// --- word-only: no APB transfer is ever generated for a sub-word access
a_subword_no_apb: assert property (
  @(posedge hclk_i) disable iff (!hreset_n_i)
  (hsel_i && htrans_i != IDLE && hsize_i != WORD) |-> ##[1:4] !$rose(|psel_o));

// --- sub-word access returns ERROR
a_subword_error: assert property (
  @(posedge hclk_i) disable iff (!hreset_n_i)
  (hsel_i && htrans_i != IDLE && hsize_i != WORD) |-> ##[1:2] hresp_o);

// --- every error is exactly the AHB two-cycle sequence
a_error_two_cycle: assert property (
  @(posedge hclk_i) disable iff (!hreset_n_i)
  (hresp_o && !hreadyout_o) |=> (hresp_o && hreadyout_o));

// --- timeout fires at exactly 16 and abandons the transfer
a_timeout_at_16: assert property (
  @(posedge pclk_i) disable iff (!preset_n_i)
  (penable_o && !pready_sel)[*16] |=> (!penable_o && !|psel_o));

// --- timeout always terminates the AHB transfer: the bus cannot hang (R-7)
a_no_hang: assert property (
  @(posedge hclk_i) disable iff (!hreset_n_i)
  (hsel_i && htrans_i != IDLE) |-> ##[1:40] hreadyout_o);

// --- unmapped window asserts no PSEL and errors
a_unmapped: assert property (
  @(posedge hclk_i) disable iff (!hreset_n_i)
  (hsel_i && htrans_i != IDLE && haddr_i[15:12] inside {4'h0, [4'hB:4'hF]})
    |-> ##[1:2] hresp_o);

// --- PSLVERR propagates as an AHB error
a_slverr_prop: assert property (
  @(posedge pclk_i) disable iff (!preset_n_i)
  (pready_sel && pslverr_sel) |-> ##[1:4] hresp_pending);

// --- hreadyout stays low until both resets have released (N-9.3)
a_dual_reset_hold: assert property (
  @(posedge hclk_i) (!hreset_n_i || !preset_n_sync) |-> !hreadyout_o);

// --- APB_DIV: PENABLE held for the configured number of cycles
a_apb_div: assert property (
  @(posedge pclk_i) disable iff (!preset_n_i)
  $rose(penable_o) |-> penable_o[*(1 << apb_div_sel)]);
```

## 12 Design decisions

| Decision | ADR |
|---|---|
| Real 125 MHz `pclk` from a toggle flop in `clk_div`, not an ICG in the bridge | ADR-0002 |
| No CDC, with the subset-of-edges proof rather than an assertion | ADR-0002 |
| Per-window `APB_DIV` as the remedy for a slow IP, not a second clock | ADR-0002 |

| Window `0x0` left unmapped rather than compacting the map | ADR-0020 |

## 13 Not implemented

| Feature | Why not |
|---|---|
| `pclk` generated by an ICG | §1.3: produces 25% duty, not the specified 50%. |
| CDC synchronisers | §7.2: the two clocks share edges. Synchronisers would add latency and imply an asynchrony that does not exist. |
| Byte/halfword support via read-modify-write | §7.13: three transfers for one, against registers with read side effects. |
| APB4 (`PPROT`, `PSTRB`) | No privilege model, no byte strobes needed. |
| Multiple outstanding APB transfers | APB is inherently one at a time. |
| Write buffering / posted writes | Would make a peripheral write's fault imprecise, so a bad write's `mepc` would point at the wrong instruction. |
| A software-visible timeout register | The timeout produces a precise fault; a status bit read afterwards adds nothing. |
| `APB_DIV` as a runtime register | §5.1: it is a property of the instantiated IP, not a firmware choice. |
| Per-window reset | All peripherals share `preset_n`. No use case for resetting one peripheral alone. |

## 14 Open items

None. OPEN-1 (peripheral IP maximum frequency) is closed by design rather than by an
answer: `APB_DIV` defaults to ÷1 and is a per-window parameter, so if an IP's interface
turns out to need more time, one parameter changes. [N-7.10] states the limit of that
remedy honestly — an IP that cannot meet 8 ns internally needs `DIVSEL`, not `APB_DIV`.
