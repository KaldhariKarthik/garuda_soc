# GARUDA: B2 exploratory physical design on ASAP7, 2026-10-13

**What this is.** The record of B2 work on 2026-10-13: SDC validation, the physical-design blocker
analysis, and the first exploratory GARUDA synthesis on ASAP7, with every command, tool version and
result.

**What it is not.** Timing closure, or any statement about TSMC 28 nm. ASAP7 is a predictive 7 nm
teaching PDK, the I/O constraints are placeholders, and STA ran before placement with ideal clocks,
no wires, no buffering and at the FF (fast) library corner.

Repo `main` at `e43672f`. No RTL, testbench or script was modified. RTL proposals P1/P2 exist only
as diffs in `flow/pd/proposals/`.

## 1. Inspection results

- **ASAP7 time unit is 1 ps** (`time_unit : "1ps"` in the liberty). The ns-valued draft
  `garuda.sdc` would have meant a 2 ps clock on ASAP7, so the ASAP7 scenarios are separate files
  in ps (`flow/constraints/asap7/`).
- **`GARUDA_SRAM_BLACKBOX` is not a black box**: it makes `rdata` a constant-0 register, so
  synthesis would constant-fold every instruction fetch and data load. It is not used. A true
  black box is applied through ORFS `SYNTH_BLACKBOXES = *sram_wrapper*`. ORFS's `mem_dump`
  check (`SYNTH_MEMORY_MAX_BITS` = 4096) would abort synthesis if any memory were built from
  flops.
- **ASAP7 fake RAMs** (ORFS `platforms/asap7/{lef,lib/NLDM}`): 17 macros, from `fakeram_32x46` to
  `fakeram_2048x128` / `fakeram7_2048x39`. **None has a write mask/byte enable** (pins: `clk ce_in
  we_in addr_in wd_in rd_out`) and none matches GARUDA's 16384x32 / 4096x32 / 1024x32 with
  `be[3:0]`. ORFS ships `platforms/asap7/fakeram.cfg` for the FakeRAM2.0 generator (not
  installed) and a mock-SRAM pattern (`designs/asap7/riscv32i-mock-sram`).
- **ICG:** ASAP7 has `ICGx*_ASAP7_75t_*` (`clock_gating_integrated_cell : latch_posedge_precontrol`,
  pins CLK/ENA/SE/GCLK). The platform marks `ICG*` dont_use for the resizer and maps the generic
  `OPENROAD_CLKGATE` to `ICGx1_ASAP7_75t_R` through `yoSys/cells_clkgate_R.v`, only when
  `OPENROAD_CLKGATE` is defined. **`GARUDA_ICG_CELL` cannot simply be enabled:** its branch has
  no instance and only `$display`/`$finish` in an `initial`, so under synthesis `gclk_o` would be
  undriven. Making it work needs an RTL edit (proposal P1).
- **Tri-states:** `tdo`, `spis_miso` (tri-state), `i2c_scl`, `i2c_sda`, `gpio0`, `gpio1` (inout).

## 4. SDC scenarios and STA

`python3 flow/constraints/asap7/gen_modes.py` writes `garuda_div{2,4,8,16}.sdc`. STA loads the
netlist with **placeholder** abstracts for the three black-box types (renamed to
`GARUDA_PH_SRAM_*` in a copy of the netlist; pins only, no timing arcs, non-physical 10x10 µm;
never for P&R) and runs `~/tools/logs/b2_sta.tcl` per mode.

**Validation.** In all four modes: 0 SDC warnings or errors after `read_sdc`; no unclocked
registers, loops or generated-clock problems in `check_setup`. Exactly **8 unconstrained
endpoints**, the 8 synchroniser D pins excluded on purpose (the spis ×3, uart ×3, boot_sel and
spim_miso first stages). gpio is absent because its input path is broken, see §3. Clock periods as
intended (ps): refclk 2000, aon_clk 4000, hclk 4000/8000/16000/32000, pclk 8000/16000/32000/64000,
tck 50000.

**SDC defect found and fixed:** defining the generated clocks with `-invert` made OpenSTA pair the
pclk → core_clk_gate latch path with a capture edge 10 ns before launch (spurious −8304 ps).
Without `-invert` the same path class is reported normally (worst latch path +1665 ps).
`gen_modes.py` was changed accordingly and all four modes rerun.

**Results** (`~/tools/garuda_pd/sta_r1/summary.txt`; pre-placement, ideal clocks, FF corner,
unbuffered nets: NOT closure):

| Mode | Worst setup | TNS | Worst hold | Notes |
|---|---|---|---|---|
| DIV2 (primary) | −3539 ps (hclk) | −85043 ps | −8.1 ps | see below |
| DIV4 | +461 ps | 0 | −8.1 ps | |
| DIV8 | +1664 ps | 0 | −8.1 ps | |
| DIV16 | +1664 ps | 0 | −8.1 ps | |

DIV2 failures, explained:
- **Unbuffered reset fan-out**, not logic. `preset_n` drives **3311 loads from one INVx1** (7.05 ns
  delay, 15.9 ns slew), which gives −3539 ps at `u_bridge.prst_ok_q/D` (pclk → hclk, timed as
  required) and −658.6 ps recovery at SPI-slave flops. The 147 ps recovery misses come from the
  same kind of net. Other high-fanout nets: tie-high 6891, `pclk` 3411, `gclk` 2459, `hclk` 1839,
  `hreset_n` 1533, core `rst_n_i` 1467. Synthesis does not buffer; floorplan/resizer and CTS would.
- **Hold −8.1 / −6.4 ps** on the `pclk_q` and `t1_q` toggle feedback: the generated clock is
  defined on the same QN pin that feeds D, so with ideal clocks the clock-to-QN delay is zero. To
  be rechecked with propagated clocks after CTS.
- The next hclk endpoint after the reset-fanout ones, `u_pc_gen.fetch_pc_o[2]`, has +2233 ps at
  DIV2 (3744 ps arrival including the launch edge).

Clock relationships checked by report: tck → core payload bounded (worst arrival 261 ps vs a
4000 ps bound); core → tck 53 ps; hclk ↔ pclk and aon ↔ hclk/pclk paths reported and timed; the
clock-gating check on `gclk`'s AND gate was inferred (+1973 ps setup, +17.7 ps hold). `refclk`
fanout = 1.

### Clock-phase defect found and fixed (`gen_modes.py`, `garuda.sdc`)
With clocks on QN pins as a plain `-divide_by 2`, STA placed aon_clk 2000 ps out of phase with hclk.
Physically, t1 toggles on each refclk rise, and t2..t4, hclk and pclk change only on t1 rises, so
every hclk rise coincides with an aon rise. Effect: hclk→aon setup was checked over 2000 ps instead
of 4000 ps (pessimistic), and hold over +2000 ps instead of the same edge (**optimistic by 2 ns**).
Fix: every derived clock now has explicit `-edges` counted in refclk edges (`-source refclk`;
QN-pin edges: aon {3 5 7}, t2 {5 9 13}, t3 {9 17 25}, t4 {17 33 49}; hclk {1, 1+D, 1+2D} on the mux
output; pclk QN {1, 1+2D, 1+4D}). Validated (`~/tools/garuda_pd/sta_r2/phase_div{2,8}.log`):
hclk→aon setup window 4000 ps and hold at the same edge (+48 ps); aon→hclk 4000 ps and same edge;
hclk→pclk one hclk period and same edge; pclk→aon, aon→pclk likewise; `sel_req_q`→`sel_act_q`
2000 ps half-cycle.

synchroniser D pins** (spis ×3, uart ×3, gpio ×2, i2c ×2, boot_sel, spim_miso); `ext_rst_n` loads
184 (183 in synth_r1), all RESETN/SETN.

| Mode | Worst setup | TNS | Worst hold |
|---|---|---|---|
| DIV2 | −3695.85 ps | −122167 ps | −8.13 ps |
| DIV4 | +304.15 ps | 0 | −8.13 ps |
| DIV8 | +1767.09 ps | 0 | −8.13 ps |
| DIV16 | +1767.09 ps | 0 | −8.13 ps |

**Why DIV8 = DIV16:** the worst path in both is `u_clk_div.sel_req_q[1]` (aon rise) →
`u_clk_div.sel_act_q[1]/D` (aon fall), a 2000 ps half-cycle in the aon_clk group. aon_clk is
refclk/2 in every mode, so this path does not depend on DIVSEL. At DIV2/DIV4 the hclk paths are
worse; at DIV8/16 hclk is slow enough that this fixed path dominates both.

**DIV2 violations are real reset-release paths, NOT to be waived.** Both start at
`u_reset_ctrl.prst_q[1]` (the preset_n release synchroniser) and go through one `INVx1` driving
**3311 loads** (7.05 ns, 15.9 ns slew):
(a) `u_soc.u_bridge.prst_ok_q/D`, −3695.85 ps: a pclk→hclk data path (the bridge samples preset_n
to hold hreadyout low until both resets have released, CLKRST §5.2 / AHB2APB §9);
(b) recovery at `g_spis.u_spis.u_core.cs_n_q/SETN`, −816 ps: reset-release timing of the pclk
domain.
Both must be shown MET after buffering (repair_design / placement-stage resizing, then
post-CTS with propagated clocks). Neither is a false path.

## 8. Proposal: mock memory dimensions and exploratory die (awaiting approval)
**EXPLORATORY ASSUMPTIONS, not SRAM estimates.** Derivation:
- Bit density from the ASAP7 fake-RAM abstracts: `fakeram7_2048x39` LEF 20.330 × 166.600 µm =
  3386.98 µm² for 79,872 bits → **0.042405 µm²/bit** (its liberty area 3353.857 µm² → 0.04199);
  `fakeram7_256x32` 8.360 × 42.000 µm = 351.12 µm² / 8192 bits → 0.04286.
- Height kept at the 2048-row abstract (166.600 µm) by column-multiplexing, so the macros stack;
  width = area / height, rounded up to the 0.054 µm placement-site pitch.

| Macro | Capacity | Organisation (assumed) | W × H (µm) | Area (µm²) |
|---|---|---|---|---|
| `garuda_sram_16384x32` (ISRAM) | 524,288 b | 2048 rows × 256 cols (mux 8) | 133.488 × 166.600 | 22,239 |
| `garuda_sram_4096x32` ×4 (DSRAM) | 131,072 b each | 2048 × 64 (mux 2) | 33.372 × 166.600 | 5,560 each |
| `garuda_rom_1024x32` (BROM) | 32,768 b | 1024 × 32 | 16.686 × 83.300 | 1,390 |
| **Total** | 1,081,344 b | | | **45,869** |

The ROM uses SRAM density (a real ROM is denser, so this is conservative). **The real boot ROM must
have the boot image built in at the foundry stage** (ROM compiler fed from the `INIT_FILE` image).
The mock can hold no contents; it only models pins and a read port.

Die (exploratory): macros in one row along the bottom edge (283.6 µm of macro width + 2 µm halos)
with standard cells above. Std-cell area 8,064.5 µm² (synth_r2).
**DIE_AREA 0 0 320 300 µm, CORE_AREA 5 5 315 295 µm** (core 89,900 µm²): macros+halos ≈ 50,790 µm²,
leaving ≈ 39,100 µm² for 8,064 µm² of std cells (≈ 21 % local density); total instance
utilisation ≈ 60 %. PHYS [N-6.3]'s 28 nm estimate for all memories (0.25–0.40 mm²) is not
comparable.
Mock models (to build after approval): ORFS hierarchical blocks; behaviour 4 rows (as ORFS's
example), address XOR-folded so every pin stays live, `be[3:0]` per-lane writes, `ce` gating,
registered read (1-cycle latency, as `sram_wrapper`), ROM without write pins. Block die forced to the
W × H above. Abstract timing comes from the mock's own logic at ASAP7: **exploratory, not SRAM
access time**. Byte-write and ROM behaviour to be checked on the mock RTL (Yosys SAT properties)
before hardening.
