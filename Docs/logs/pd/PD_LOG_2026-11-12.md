## 1. Clock divider: t2, t3 and t4 on t1 (PD-11)

### 1.1 Change
`rtl/clk_div/clk_div.v`: t2, t3 and t4 were a ripple chain (t3 clocked by t2, t4 by t3). They are
now three flops clocked by t1, with the same waveforms:
`t2 <= ~t2`, `t3 <= t3 ^ ~t2`, `t4 <= t4 ^ (~t2 & ~t3)`. The rule [N-7.19]/[R-10] (refclk reaches
one flop only) is kept: the option "all divider flops on refclk" was not used because it breaks it.

## 2. Hold robustness (PD-12)

`flow/constraints/asap7/gen_modes.py` adds to the four DIVSEL SDCs (assumptions, provisional):
`set_clock_uncertainty -hold 30` on every clock, and a flat on-chip-variation derate, early 0.95
and late 1.05, on cell and net delays (ASAP7 has no AOCV/POCV tables; 5 to 10 % is the usual flat
value before a PDK). The tool removes common clock path pessimism (CRPR).

Effect on the old layout (pnr_r7, routed, SPEF): hold -55 to -128 ps on 399 to 1,144 endpoints at
SS/TT/FF. The +1.79 ps of pnr_r7 had no margin.

## 3. Multi-corner implementation and STA (PD-13)

### 3.1 Choice of the implementation corner
pnr_r7's layout at SS: setup -898 ps on 1,377 endpoints (DIV2, worst path `fetch_pc_o` in the
instruction fetch); TT +665 ps; FF met. Decision: pnr_r8 is built at SS (`CORNER=WC`: synthesis,
placement, CTS and the post-route repairs see the SS libraries), and hold is repaired at FF after
CTS. The memory blocks are hardened at SS too; `run_block_libs.sh` writes their SS, TT and FF models.

### 3.2 Hold repair over modes and corners
Scenes: div2_WC (setup protection), div16_WC, div2_BC, div4_BC, div8_BC, div16_BC. Before: worst
hold -145.34 ps (div8_BC), 1,277 endpoints. `repair_timing -hold`: 1,675 buffers, 2,264 s.
The first attempt (5 scenes, 17:24 to 19:00) was stopped: see TOOL-A14 (two scenes that shared one
mode across two corners gave wrong slacks, -320 ps where the truth was +0.31 ps). After the fix,
one mode per scene.

## 4. Memory integration

No real macro views exist for ASAP7. FakeRAM2.0 (in ORFS) was tried for GARUDA's shapes: it has no
write mask, its timing is a fixed set of placeholder values, and it makes 16384x8 = 4.18 x 1,327 µm and
16384x32 = 16.72 x 1,327 µm (the die is 300 µm high). The mock macros stay (D-35).

## 5. Power with simulated activity (PD-14)

Workload: `t_chip_integ` on the RTL under Verilator with `--trace-saif` (374.1 µs, 36,430
instructions, DMA and peripherals, 8,573 hclk cycles clock-gated; the program passes). The SAIF is
hierarchical and the netlist flat, so `saif_to_activity.py` and `power.tcl` match each register bit
to its flop: 7,950 of 8,004 flops annotated, plus ports; 117 clock-rate nets left to the clocks.
Routed database, SPEF, DIV2 constraints. Power in W:

| Corner | Default activity (OpenSTA) | Simulated activity | Sequential / combinational / clock (simulated) |
|---|---|---|---|
| TT | 4.24e-3 | **5.32e-3** | 1.12e-3 / 2.03e-3 / 2.17e-3 |
| FF | 5.52e-3 | 6.97e-3 | 1.43e-3 / 2.68e-3 / 2.86e-3 |
| SS | 3.45e-3 | 4.29e-3 | 0.90e-3 / 1.69e-3 / 1.71e-3 (leakage 0.12e-3 at 100 °C) |

Limits: the memory macros report 0 W (mock models carry no power data), only flops and ports are
annotated (OpenSTA propagates into the logic between), one workload, no I/O pads.
